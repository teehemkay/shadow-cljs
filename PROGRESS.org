* In plain terms

This section says the same thing as the rest of the document for a reader who doesn't live in the stack. The technical sections remain the source of truth.

*What we're building.* shadow-cljs turns ClojureScript into JavaScript and gives a live programming session against the running program. This fork lets that running program be Bun instead of Node, and keeps the Bun process alive while you work.

*Why we do it this way.* The fork stays as close to upstream as it can, so pulling in new upstream versions stays cheap. Fixes to upstream code are kept small; the lint rule here counts only lines the fork changed.

*The words that keep coming up.*
- Managed runtime :: the Bun process the fork starts and stops alongside a watched build.
- Worker :: shadow-cljs's per-build process that compiles and owns that runtime.
- Upstream sync :: merging the original project's newer releases into the fork.

*Where we are right now.* Keeping the Bun process alive inside shadow-cljs turned out to cost more than it was worth: most of the fork's changes, and a conflict at every upstream update. The fork will stop doing it and keep only the setting that chooses Bun. A small script shared by every project will start Bun instead, so the daily workflow stays the same. The fork's half is planned and waiting for review.

* Detailed status

** Drop the managed runtime — IN PROGRESS

*Takeaway:* the design converged on [2026-10-29 Thu], and the fork's plan is written and spiked clean. Next is =/apr= on the plan, once tmk answers the open questions below.
- *What it decides.* The fork keeps the =:js-runtime= selector and starts no process for a watched build. A bb launcher in bunbushka starts, restarts and stops Bun, and the consumers' =bb dev= calls it. [[id:20261028T164829.836099][The design]] carries the evidence and the review record.
- *Release order.* (1) the fork releases without the managed runtime; (2) bunbushka ships the launcher and its template; (3) kiln and ik switch, and agent-skills' skill is rewritten. One plan per step, ruled by tmk.
- *Step 1's plan.* [[id:20261029T220537.596609][Two tasks]]: Task 1 restores =worker.clj= and =worker/impl.clj= to upstream, trims =repl_impl.clj= to its =node-repl*= hunks, and replaces the managed suite with =shadow.cljs.js-runtime-watch-test=; Task 2 rewrites the docs. [[my:shadow-cljs/docs/explorations/2026/2026-10/2026-10-29-drop-managed-runtime-plan-spike.org][Its plan spike]] replays both tasks in order and verifies clean.
- *Open for tmk:*
  - Confirm the test deletions by name: =managed_runtime_test.clj= and its three probes, plus =test-managed-runtime-is-opt-in= and =test-bootstrap-source-keeps-runtime-alive=.
  - Accept two removals beyond the spec's list: =explicit-js-runtime?=, and =node-repl*='s filtering of =:js-runtime=.
  - Choose execution: native (recommended) or subagent-driven.

** Sync to upstream 3.5.7 — DONE

*Takeaway:* merged to =master= and released as =3.5.7-bun= on [2026-10-19 Mon], CI green on both jobs.
- 42 upstream commits; only =project.clj= and =server/worker.clj= conflicted. The merge commit records each resolution.
- Upstream reshaped the worker's =:failure-data=; the fork's check still holds, and its comment was corrected.
- shadow-http 0.1.8 → 0.1.11 left the WebSocket classes untouched, so the fork's copied handler stays valid. No dashboard source changed, so no UI rebuild.
- The release notes must name one behaviour change: under a running watch, =api/compile= returns =:ok= or =:error= rather than =:done=. The CLI and kiln, bunbushka and ik are unaffected.
- The publishing doc's sync procedure now reads upstream's worker and API changes, runs the =src/repl= suites, and checks whether the dashboard needs a rebuild.

** First-compile wait — DONE

*Takeaway:* an eval that arrives during a build's first compile now waits for the managed runtime instead of failing. Released as =3.5.7-bun.2= on [2026-10-24 Sat]; kiln moved to it, and agent-skills' ClojureScript session test passes again. Tracked in [[id:20261021T185802.026641][todo.org]].
- *Bug.* Since =3.5.7-bun=, =bd org spike-verify='s ClojureScript sessions on kiln got "No available JS runtime": they evaluate during the first compile, and =await-managed-runtime= returned at once when no process existed yet.
- *Fix.* The eval waits up to 5 s for the first successful compile, then for the process as before. The docs state the limits: the window counts per eval, so a longer first compile still fails and a never-compiled build costs every eval 5 s.
- *Not built.* A busy signal that would count from the compile's start; weighed and set aside. The verifier is to wait for a runtime itself, handed to the agent-skills session.
