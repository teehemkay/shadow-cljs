* In plain terms

This section says the same thing as the rest of the document for a reader who doesn't live in the stack. The technical sections remain the source of truth.

*What we're building.* shadow-cljs turns ClojureScript into JavaScript and gives a live programming session against the running program. This fork lets that running program be Bun instead of Node, and keeps the Bun process alive for you while you work.

*Why we do it this way.* The fork stays as close to upstream as it can, so pulling in new upstream versions stays cheap. Fixes to upstream code are kept small; the lint rule here counts only lines the fork changed.

*The words that keep coming up.*
- Managed runtime :: the Bun process the fork starts and stops alongside a watched build.
- Worker :: shadow-cljs's per-build process that compiles and owns that runtime.
- Relay :: shadow-cljs's internal message switchboard between the worker, editors and runtimes.

*Where we are right now.* The latest round of fixes is done and saved. The project that depends on this fork, kiln, gets them only after a new release is published.

* Detailed status

** Managed-runtime follow-ups — DONE

*Takeaway:* merged at =c1858fc4= on [2026-10-19 Mon]; the leftovers are decisions, listed under the pending and deferred rows.
- Expected failures in the tests are captured and asserted instead of printed.
- A fork-owned copy of shadow-http's websocket handler ends its write loop quietly when the peer dies mid-send; the worker also leaves the relay before killing its runtime.
- node-repl under bun now loads its compiled files; node needs =npm install= in this checkout.
- =api/watch= with a config map returns =:already-watching= for a running build, an upstream bug fixed in the fork.
- The bun probe throws on anything but absence and does not cache a failure.

** Relay websocket and watch printer — DONE

*Takeaway:* merged on [2026-10-19 Mon] after three review rounds on the websocket work and one on the printer.
- The fork's websocket handler closes the connection whenever its write loop ends: nothing for a departed peer, 1000 when the relay drops a client, and a logged fault with 1011 otherwise. Ending also releases a reader blocked on a full input channel.
- The access-denied upgrade now says so and disconnects.
- =util/stdout-dump= buffers 1024 printable messages, sliding, and closes its channel when its output disconnects.
- Left for upstream: a peer that never answers a server close keeps its socket, and shadow-http answers its own close twice.

*Takeaway:* merged on [2026-10-19 Mon]; two jobs run on every push and pull request, both green.
