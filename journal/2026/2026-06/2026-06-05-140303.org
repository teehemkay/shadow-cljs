* Project Notes

** Key Decisions

- Coordinates =org.clojars.teehemkay/shadow-cljs=: the upstream =thheller= group is owned and undeployable; =org.clojars.<username>= is auto-verified for any account, so it needs no DNS.
- Version scheme =<upstream>-bun= (=3.3.7-bun=): keeps the upstream base visible while marking the fork. Released Clojars versions are immutable, so re-release means bumping the suffix.
- Published a compiler/library-only jar — deliberately skipped =./build-all.sh=. The fork exists for =:js-runtime=, consumed as a build-tool dep, not for the =localhost:9630= dashboard.

** Gotchas

- The =:ui= and =:build-report= shadow-cljs builds output straight into =src/ui-release/...=, which the jar bundles via the =:provided= profile (=src/ui-release= on its source-paths). That's why a plain =lein install= picks them up with no extra wiring — but only if they've been built.
- The dashboard CSS build (=src/dev/build.clj=, =build/css-release=) indexes a *sibling* =../shadow-grove/src/main= checkout, not the =com.thheller/shadow-grove= Clojars dep. That sibling is absent here, and =packages/ui/node_modules= is empty. So "build the full UI" means reconstructing the maintainer's local dev layout — far more than running one script. The CSS step is REPL-driven (not a CLI command), which compounds it.
- First-ever deploy of a new artifact prints "Could not find metadata ... maven-metadata.xml in clojars" — this is *not* an error; there's no prior metadata to merge, so lein creates and sends it.
- Leiningen resolves =:env/clojars_username= to the =CLOJARS_USERNAME= env var (uppercases the name after =env/=); =:password :env/clojars_password= → =CLOJARS_PASSWORD=.

* Technical Insights

** Validate the build before any irreversible publish

Ran =lein install= (full jar + pom + local-repo install) before =lein deploy=. Same build path, but reversible — it surfaces compile/packaging failures while a re-run still costs nothing. Only after that did the immutable upload happen. Cheap insurance against burning a version number on a broken artifact.

** Inspect the artifact, don't assume completeness

=jar tf | grep= on the built jar revealed the dashboard JS was absent before anything shipped. The build "succeeding" said nothing about whether the bundle was complete — the contents listing did. Worth doing whenever a jar's payload comes from generated/committed assets rather than pure source.
