* Project Notes

** Key Decisions

- *The worker owns the process; evals only read its state.* One rule: after a successful compile, a managed build with no live process gets one, and a build that is no longer managed loses its. An eval waits only while a new process is inside its 5 s connect window, counted from the process's start, then says why there is no runtime, with that run's log.
- *Which builds qualify is asked of the compiled build*: =:js-runtime= in the merged config (where =--js-runtime= lands through =:config-merge=) and the node REPL client among its provides. A plain =:node-test= build runs its suite and exits, so it gets none.
- *Restart and replacement policies were built and removed*, [[orgit-rev:~/dev/my/shadow-cljs::3806490da122cf409c54081c5d994068af91f9aa][3806490d]]. Each depended on timing inside the compile loop and on the others, and four review rounds kept finding new interactions. The architecture doc records them as rejected.
- *A =.cljfmt.edn= that rewrites nothing* keeps an agent's formatting hook from re-indenting upstream code, once that hook reads the project's config.

** Gotchas

- Starting the runtime from inside =repl-impl/do-repl= looked like the one place every path passes. It was, and that is why it failed: a blocking request to the worker from the eval loop could hang forever on a failed launch and deadlock a build hook on the worker thread.
- =build-failure= stores =(ex-data e)=, which is nil for a plain exception, so "did the compile fail" is =(contains? state :failure-data)=, never its value.
- Test fixtures written before the change hid the =:node-test= problem: the March plan's manual check used =:ui-driven true=, the one shape that works.
